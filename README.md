【引き継ぎ用 README】統合レポート作成
対象ソース：bank_integrated_report（Python / Streamlit）

■ 1. アプリの目的
AFF（アフィリエイト）と運用型広告（検索・ディスプレイ）の「プラン」と「実績」を取り込み、以下の3種類の表を統合したExcelレポートとして出力する。
・合算：検索／ディスプレイ／アフィリエイト／合計のCV・コスト・CPAについて目標と実績を比較
・日別：対象月の日付ごとの実績、日割り目標、目標vs実績
・媒体別：運用型の媒体カテゴリ／媒体名称／媒体詳細別、およびAFFサイト別のコスト・CV・CPA

■ 2. 起動と必要ファイル
起動例：streamlit run bank_integrated_report.py
必要なPythonパッケージ：streamlit、pandas、openpyxl（標準ライブラリ：calendar、io、math、re、zipfile、xml.etree.ElementTree、dataclasses、copy、datetime、pathlib、typing）。
アプリと同じフォルダに output_template.xlsx があれば、そこにある「合算」「日別」「媒体別」シートへ書き込む。テンプレートがない場合は同名の3シートを新規作成する。ただし見出し・書式を維持したい場合はテンプレートを配置すること。
※このソース単体から、実際のテンプレートのセル配置・装飾の正しさまでは確認できない。

■ 3. 操作手順
① アプリを開く。
② 左側「AFF」にAFFプラン（.xlsx/.xlsm）とAFF実績（.csv）をアップロードする。
③ AFFプランの対象シートを選ぶ（非表示シートも選択可能）。
④ 右側「運用型」に運用型プラン（.xlsx/.xlsm）と運用型実績（.xlsx/.xlsm）をアップロードする。
⑤ 運用型プランの対象シートを選ぶ（非表示シートも選択可能）。
⑥ 4ファイルと両プランシートが揃ったら「統合レポートを作成」を押す。
⑦ 画面の「合算」「日別」「媒体別」で確認し、「統合レポートをExcelでダウンロード」を押す。
出力名：統合レポート_YYYYMM.xlsx（YYYYMMはデータから推定した対象年月）。
※集計エラーは画面に例外として表示される。

■ 4. 入力データの仕様
【AFFプラン】
・選択したシートの W7、AI7、AU7、BG7、BS7 を合計してCV目標にする。
・Y7、AK7、AW7、BI7、BU7 を合計してコスト目標にする。
・A列の値が入ったセルからサイト名を抽出し、AFF実績の照合対象とする（文字列の前後空白・全角空白を正規化）。
・Excel内に保存済みの計算結果（キャッシュ値）を読み取る方式。数式の再計算は行わない。

【AFF実績CSV】
・必須列：「パートナーサイト名」「件数」「成果発生日時」「グロス」。
・文字コードは cp932 → utf-8-sig → utf-8 の順に試行。
・AFFプランから抽出したサイト名と一致する行だけを集計する。
・CV＝件数合計、コスト＝グロス合計、日付＝成果発生日時の日付部分。
・サイト名が一致しない行は集計対象外。画面に「AFF一致サイト：一致数／プランサイト数」を表示。

【運用型プラン】
・選択したシートをopenpyxl(data_only=True)で読む。
・A列＝媒体カテゴリ、B列＝媒体名称、F列＝媒体詳細、K列＝コスト、L列＝CV。
・検索／ディスプレイについてF列が「TOTAL」の行を合算して目標を算出。A列が空白の行は直前のカテゴリを引き継ぐ。
・媒体別の照合元として、A列が「検索」「ディスプレイ」、B/F列が空でなく、F列がTOTAL以外の行を抽出し、重複を除去する。
・注意：目標TOTAL集計ではA/B列を直前値で補完するが、媒体別の抽出では補完しない。結合セル・省略表記の行は媒体別に取り込まれない可能性がある。

【運用型実績】
・「Search_合計」「Display_合計」（【】付きの表記も許容）を参照。
・各シートの M22＝CV、I22＝コストをカテゴリ全体の実績として取得。
・日別は23～99行を走査し、A列またはB列から日付列を自動判定。M列＝CV、I列＝コスト。
・媒体別は以下の非表示ローデータシートのうち存在するものを読む：
  【非表示】GDNローデータ、Metaローデータ、SmartNewsローデータ、Xローデータ、YDAローデータ、MSAローデータ、Yahooローデータ、YouTubeローデータ、Googleローデータ。
・各ローデータのA列＝キャンペーン名、G列＝コスト、H列＝CVとして取り込む。
・上記の合計シート・ローデータシートに必要なデータがないと、エラーまたは0集計となる。

■ 5. 集計ロジック
【合算】
・検索、ディスプレイ、AFFの各目標／実績を並べ、合計行は各カテゴリの数値を合算する。
・CPA＝コスト÷CV。CVが0なら0。
・「TVA」はコード上「目標÷実績」（CV・コスト・CPAとも）。通常の実績達成率（実績÷目標）とは逆向きなので、業務上の定義を必ず確認すること。

【日別】
・検索／ディスプレイの日別データと、AFFの成果発生日別集計を対象月の日付に結合する。
・各カテゴリの日割りCV目標＝月間CV目標÷月の日数、日割りコスト目標＝月間コスト目標÷月の日数。
・日別の目標CPAは月間目標コスト÷月間目標CV（毎日同じ値）。
・「目標vs実績」は各指標の目標÷実績。合計の比率はカテゴリ別比率の単純合計ではなく、合算数値から計算する。
・対象年月は、運用型の日別とAFFの一致データに含まれる最も古い日付から推定。日付がなければ実行日の年月。

【媒体別】
・運用型プランの媒体カテゴリ・媒体名称・媒体詳細を基準に、実績ローデータのキャンペーン名と突合。
・媒体名称はGSA→GAD_/GSA_、YSA→YSS_/YSA_、YDN→LYDA_/YDA_/YDN_、P-MAX→PMAX_等の接頭辞で照合。
・媒体詳細は「公営競技」「子供口座」「デビットカード切り出し」「円預金」「カード」などをキャンペーン名に含むかで判定。円預金から子供口座を、カードからデビットを除く条件がある。
・一致するキャンペーンのコスト・CVを合算し、CPAを算出。
・AFFは一致サイトごとにコスト・CV・CPAを算出し、媒体カテゴリ「AFF」で追加。
・注意：運用型ローデータは全シートを通して走査するため、同じキャンペーンの重複掲載や複数のプラン行への重複マッチがあると二重計上の恐れがある。媒体別合計とカテゴリ全体の実績は独立した集計なので一致する保証はない。

■ 6. Excel出力先と書式
・「合算」：3～6行に検索、ディスプレイ、アフィリエイト、合計を出力。A列が区分、B～J列がCV・コスト・CPAの目標／実績／TVA。
・「日別」：4行目以降に日付と各区分の実績／目標／目標vs実績を出力。日付はm/d表示。
・「媒体別」：1行目に「媒体カテゴリ」「媒体名称」「媒体詳細」「コスト」「CV」「CPA」、2行目以降にデータを出力。
・ワークブック内のセルのフォント名をMeiryo UIへ変更する（既存の太字・サイズ・色は維持）。

■ 7. 保守担当者向け：主な関数と修正場所
・AFF目標セルの変更：AFF_CV_CELLS、AFF_COST_CELLS
・AFFプラン読込：read_aff_plan
・AFF CSVの列名・抽出条件：read_aff_actual
・運用型プランのTOTAL行集計：_operational_plan_rows、read_operational_plan
・運用型プランの媒体別一覧：read_operational_plan_media
・運用型実績の合計／日別：read_operational_actual、detect_daily_date_column
・媒体別の参照シート：OPERATIONAL_RAW_SHEETS
・媒体名称とキャンペーン名の対応：_media_name_matches_campaign
・媒体詳細とキャンペーン名の対応：_detail_matches_campaign
・媒体別集計：read_operational_media、build_media
・合算／日別：build_summary、build_daily
・Excel出力：export_excel（テンプレートのシート名「合算」「日別」「媒体別」に依存）
・画面／アップロード／ダウンロード：main
・高速読込：FastXlsxReader（xlsxのZIP内XMLを直接読み、非表示シートも取得する）

■ 8. 重要な注意事項・既知のリスク
① Excel数式の計算は行わない。入力ファイルをExcel等で再計算・保存してから使用し、保存済みの計算結果が正しいことを確認する。
② TVAの計算式は「目標÷実績」。達成率として説明・利用する前に業務定義を確認する。
③ AFFのサイト照合は名称一致。名称表記ゆれ・余分な行・未一致サイトで数字が欠落する可能性がある。
④ 運用型の媒体別マッチングはキャンペーン命名規則に依存。新しい媒体・商品・命名規則が増えたら対応表／判定条件を見直す。
⑤ 対象年月は最も古い日付から推定する。複数月が混在したデータでは意図しない月が選ばれ、日別表には選択された1か月分しか並ばない可能性がある。
⑥ 日別の運用型は23～99行を読む。入力様式変更時は行範囲と日付列判定（23～60行）を見直す。
⑦ 日別実績に同一日付が複数行ある場合、結合時に日付行が増える可能性がある。入力が日別1行か確認する。
⑧ FastXlsxReaderは独自のZIP/XML解析。Excel内部構造やシート参照パスの形式が異なるファイルでは読み込みに失敗する可能性がある。
⑨ テンプレートが存在する場合、「合算」「日別」「媒体別」シートが必要。テンプレート側の余分な行や数式・書式の残存も確認する。
⑩ 作成結果はStreamlitのsession_stateに保持される。ファイルを入れ替えた直後、再実行前に前回の結果が表示される場合があるため、必ず「統合レポートを作成」を押し直す。

■ 9. 引き継ぎ時の動作確認チェック
□ 4ファイルをアップロードし、正しいプランシートを選択できる。
□ AFF一致サイト数が想定どおりである。
□ AFFプランの指定セル合計と、AFF実績の一致サイト集計が手計算と合う。
□ 運用型のTOTAL行から検索／ディスプレイ目標が正しく取得される。
□ Search_合計／Display_合計のI22・M22と合算実績が合う。
□ 日別の日付・CV・コストと対象年月が想定どおりである。
□ 媒体別のキャンペーン照合結果に漏れ・重複がない。
□ TVAの定義を業務担当者と確認した。
□ 出力Excelの3シート、書式、ファイル名を確認した。
□ 数式を含む入力Excelを再計算・保存した場合も同じ集計結果になる。

■ 10. 補足
本書は提供されたPythonコードの実装に基づく。入力サンプルやoutput_template.xlsxそのものは確認していないため、具体的な業務データとの整合性は実ファイルで検証すること。
